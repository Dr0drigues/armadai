# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

ArmadAI is a declarative compiler written in Rust (edition 2024). A team of agents (agents, skills, flows, gates, hooks) is described once, then compiled by `armadai link` into the native files of Claude Code, Codex, OpenCode and Copilot. ArmadAI does not run agents: there is no execution engine, no TUI, no web UI. The binary is named `armadai`; without arguments it prints the help.

Commands: `link`, `unlink`, `list`, `inspect`, `graph`, `flow` (`status`, `stats`), `journal` (`add|show`), `grant`, `revoke`, `validate`, `migrate`, `new` (`agent|flow|automation|skill|command`, or a guided menu), `init`, `pack` (`add|sync|status|update|pin|unpin|new|test`), `skills`, `models` (`check|update|list|tiers|sync`), `config`, `update`, `completion`.

The refocus (what was removed, kept and frozen) is specified in `docs/superpowers/specs/2026-10-09-step0-retrait-surfaces-design.md`.

## Build & Test Commands

There is a single configuration (no optional cargo features), so there is a single barrier, identical to CI:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test --no-fail-fast
cargo build -p armadai-core   # portability guard: the core builds standalone
cargo build -p armadai-model  # same guard for the pure model crate

# Run a single test
cargo test --no-fail-fast test_name

# Run with debug logs
RUST_LOG=debug cargo run -- list
```

CI (`.github/workflows/ci.yml`) runs fmt, clippy, test, build (`cargo build --release` plus the core and model guards) and Conventional Commits; `audit.yml` runs the security audit. `.mise.toml` mirrors these as tasks.

## Architecture

**Flow**: `.armadai/` (the canonical model) -> `armadai_model::load_checked` (any error stops) -> one plan per target (`compile/`: `claude.rs` and `opencode.rs` adapters, `legacy_targets.rs` feeding the Codex/Copilot linkers) -> writes (whole files via `linker::manifest::write_files`, files shared with the user — root `CLAUDE.md` block, `settings.json` hooks, owned keys of `opencode.json` — via `compile/patch.rs`) -> conformance report (`compiled` / `approximated` / `not-compiled`, `--json`). `link` never touches the network (only `init --pack` on a local miss, or for a versioned pack of a source whose cache does not know its version yet, `pack sync`, `pack add`, `pack update`, `skills sync`/`add`, `models sync` and `update` do); `unlink` removes what `link` wrote, guided by the link manifest. A legacy project is refused by every project command except `migrate`.

**Where things live**:
- `crates/armadai-model`: the canonical project format (`.armadai/project.yaml`, `agents/`, `skills/`, `flows/`, `automations/`): strict types, loader with positioned diagnostics, semantic validator (stable codes), canonical writer, JSON Schemas (`schemas/v1/` at the repository root, regenerated by `cargo run -p armadai-model --example gen_schemas`). Pure: serde, serde-saphyr, serde_json, thiserror, schemars only — no other workspace crate, no clap/tokio/network. Format and codes: `docs/wiki/project-format.md`. `pack.rs` (the pure merge of a project onto the pack it references) and `pack_vars.rs` (`{{var.name}}` substitution) are in it too.
- `crates/armadai-core`: the legacy model, kept for what still reads it — `migrate` (and through it `init --pack` for a legacy pack, one without `format: 1`): agent model and parser (`agent.rs`, `agent_decl.rs`, `agent_source.rs`, `parser/`, `project.rs`), skills and the native starter packs (embedded via `include_dir`), model resolution (the tier table built in as `data/models.json`, read by `model_table.rs`, shown by `armadai models tiers`, proposed at release time by `mise run models-refresh`) and model aliases (read by `models` on canonical agents), the legacy `orchestration/` declaration types. It also holds `test_support.rs` (env isolation).
- `crates/armadai`: the binary — `cli/` (commands), `compile/` (plan, report, Claude and OpenCode adapters, patching of shared files, legacy targets), `linker/` (the Codex/Copilot linkers and `manifest.rs`, the record of what link wrote), `claude_adapter/policy_gate.rs` (the delegation gate on the flows), `cli/new.rs` + `new_target.rs` + `new_wizard.rs` (creation: guarded single-file writes, undo on a new error, pure `plan_*` behind the wizards), `cli/native_pack.rs` (native pack install by white list), `worktree.rs` (the git directory and main checkout of a checkout, read from `.git` by hand), `pack/` (pack management: source cache and versions, `pack.lock`, the effective view of a project that references a pack, copy-mode updates, `vars.rs`, the referent registry; commands in `cli/pack.rs`), `cli/graph.rs` (Mermaid), `journal.rs` + `cli/journal.rs` (the lot journal: one JSONL file per lot under the main checkout's `.armadai/state/`), `migrate/` (legacy project -> `armadai-model`), `skills_registry/`, `starters_registry/`, `templates/`, and the integration tests and golden outputs in `tests/`.
- `frozen/armadai-audit/`: the former `audit` command, frozen. It is outside the workspace and outside CI (its own `Cargo.lock`). Do not extend it; touch it only to keep it compiling when a crate it depends on changes (it vendors the model-registry cache reader in `src/vendored/`), and check it with `cd frozen/armadai-audit && cargo check --all-targets && cargo test`.

**State (steps 0-3 of v1 merged, step 3 in #472)**: every project command reads `.armadai/project.yaml` only; `armadai migrate` converts a legacy project (backup in `.armadai/.migrated/<ts>/`); `new`, native starter packs, flow templates and `graph` (Mermaid) are delivered. OpenCode 2.x has its own adapter (step 4, lot A: `docs/superpowers/specs/2026-10-21-step4-opencode-design.md`); Codex and Copilot get their former output, fed from the model, with `not-compiled` report lines for what they do not cover yet. Specs: `docs/superpowers/specs/2026-10-12-step1-model-validator-migrate-design.md`, `docs/superpowers/specs/2026-10-12-step2-link-claude-design.md`, `docs/superpowers/specs/2026-10-13-step3-guided-creation-starters-design.md`.

**Non-obvious facts**:
- `crates/armadai` is **binary-only** — no `lib.rs`. `cargo test --lib` there returns "0 passed" with **no error**; use `--bin armadai` or `--test <name>`.
- There is no execution engine: flows are guidance (`CLAUDE.md` for Claude, `.opencode/armadai-team.md` for OpenCode) plus, under `policy.delegation: strict`, links enforced by the gate (Claude Code) or by native `permission.task` rules (OpenCode). The legacy `OrchestrationPattern` is read only by the legacy parser (for `migrate`).
- The lock a command reads is first the **pin of its checkout** (`<git dir>/armadai/pack.lock`, written by `armadai pack pin`, never by anything else), else `.armadai/pack.lock`: `pack::lock::read` is the single reader (`read_committed` for the committed file alone), so the gate and the `grant` hook decide on the pinned pack too. `lock::write` refuses under a pin, and `pack update`/`pack add` refuse before the network (`docs/wiki/starter-packs.md`).
- The old response-marker protocol (`ARMADAI_DELEGATE`/`END`/`META`) was removed: delegation goes through each tool's native mechanism. On Claude Code, the `description` of a delegation to an agent that holds a step starts with a `[flow/step#lot]` marker (required by the gate under `policy.delegation: strict`, recorded for `flow status` and `flow stats`), and a handback may end with a `REF: <ref>` line (the `STATE:` line is unchanged). The `PreToolUse` policy gate (`armadai __claude-policy-gate`) is installed by `link` in `settings.json` under `policy.delegation: strict` and reads `.armadai/project.yaml` at runtime (see `docs/wiki/policy-gate.md`).
- `policy.grants` declares named permission levels. `link` compiles each `Bash(...)` rule into a `PermissionRequest` hook running the hidden command `armadai __claude-grant <level>` (inactive until `armadai grant <level>` writes `.armadai/state/grants.yaml`; `armadai revoke` ends it), and owns two `deny` rules guarding that state. A level is a convenience, not a security boundary (see `docs/wiki/link.md#permission-levels-grant`).
- Test env isolation lives in `armadai_core::test_support` (behind the core's dev-only `test-support` cargo feature) and is **not reentrant** — two guards on one thread deadlock.

**Agent definition** lives in `.armadai/agents/<id>.md` (no user library any more); an agent with `from:`/`vars:` is an instance of a project template `.armadai/templates/<id>.md`, rendered at load time in `armadai-model` (`agent_templates.rs`), so the adapters only see rendered agents and the writer keeps the instance form. Templates in `crates/armadai/templates/*.md` are canonical agents (frontmatter with a default description); `new agent` sets description/tier/skills on the parsed frontmatter and renders `{{name}}`, `{{stack}}`, `{{description}}` in the body only. Flow templates (`pipeline`, `review-loop`, `plan-build-verify`, `fan-out`) and the Mermaid export are pure functions of `armadai-model` (`templates.rs`, `mermaid.rs`); `entry_steps` there is the one definition of an entry step (validator and gate).

**Config** lives in `~/.config/armadai/` (user: templates, registries) and, per project, `.armadai/project.yaml`.

## Git Conventions

- **Branch model** (master-only): `master` (default/trunk), `release/*` (release-line stabilization), `feature/*` branches. No `develop`.
- **Conventional Commits** enforced by `.githooks/commit-msg` hook and CI. Types: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `ci`, `perf`, `style`, `build`, `revert`
- **PR process**: Always squash merge to `master`, and merge only when Dimitri's brief authorises it. Before merging: check for Dependabot PRs, verify CI passes (all 6 checks: fmt, clippy, test, build, conventional commits, audit — one single configuration, no feature matrix).
- Enable hooks after clone: `git config core.hooksPath .githooks`

All communication with the user must be in **French**. Code, comments, and commit messages remain in English.
