# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

ArmadAI is a declarative compiler written in Rust (edition 2024). A team of agents (agents, skills, flows, gates, hooks) is described once, then compiled by `armadai link` into the native files of Claude Code, Codex, OpenCode and Copilot. ArmadAI does not run agents: there is no execution engine, no TUI, no web UI. The binary is named `armadai`; without arguments it prints the help.

Commands: `link`, `unlink`, `list`, `inspect`, `graph`, `validate`, `migrate`, `new` (`agent|flow|automation|skill`, or a guided menu), `init`, `skills`, `models`, `config`, `update`, `completion`.

The refocus (what was removed, kept and frozen) is specified in `docs/superpowers/specs/2026-10-09-step0-retrait-surfaces-design.md`.

## Build & Test Commands

There is a single configuration (no optional cargo features), so there is a single barrier, identical to CI:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test --no-fail-fast
cargo build -p armadai-core   # portability guard: the core builds standalone
cargo build -p armadai-model  # same guard for the pure model crate

# Run a single test
cargo test --no-fail-fast test_name

# Run with debug logs
RUST_LOG=debug cargo run -- list
```

CI (`.github/workflows/ci.yml`) runs fmt, clippy, test, build (`cargo build --release` plus the core and model guards) and Conventional Commits; `audit.yml` runs the security audit. `.mise.toml` mirrors these as tasks.

## Architecture

**Flow**: `.armadai/` (the canonical model) -> `armadai_model::load_checked` (any error stops) -> one plan per target (`compile/`: `claude.rs` adapter, `legacy_targets.rs` feeding the Codex/Copilot/OpenCode linkers) -> writes (whole files via `linker::manifest::write_files`, files shared with the user — root `CLAUDE.md` block, `settings.json` hooks — via `compile/patch.rs`) -> conformance report (`compiled` / `approximated` / `not-compiled`, `--json`). `link` never touches the network (only `init --pack` on a local miss, `skills sync`/`add` and `update` do); `unlink` removes what `link` wrote, guided by the link manifest. A legacy project is refused by every project command except `migrate`.

**Where things live**:
- `crates/armadai-model`: the canonical project format (`.armadai/project.yaml`, `agents/`, `skills/`, `flows/`, `automations/`): strict types, loader with positioned diagnostics, semantic validator (stable codes), canonical writer, JSON Schemas (`schemas/v1/`, regenerated by `cargo run -p armadai-model --example gen_schemas`). Pure: serde, serde-saphyr, serde_json, thiserror, schemars only — no other workspace crate, no clap/tokio/network. Format and codes: `docs/wiki/project-format.md`.
- `crates/armadai-core`: the legacy model, kept for what still reads it — `migrate` (and through it `init --pack` for a legacy pack, one without `format: 1`): agent model and parser (`agent.rs`, `agent_decl.rs`, `agent_source.rs`, `parser/`, `project.rs`), skills and the native starter packs (embedded via `include_dir`), model resolution (static tier table) and model aliases (read by `models` on canonical agents), the legacy `orchestration/` declaration types. It also holds `test_support/` (env isolation).
- `crates/armadai`: the binary — `cli/` (commands), `compile/` (plan, report, Claude adapter, patching of shared files, legacy targets), `linker/` (the Codex/Copilot/OpenCode linkers and `manifest.rs`, the record of what link wrote), `claude_adapter/policy_gate.rs` (the delegation gate on the flows), `cli/new.rs` + `new_target.rs` + `new_wizard.rs` (creation: guarded single-file writes, undo on a new error, pure `plan_*` behind the wizards), `cli/native_pack.rs` (native pack install by white list), `cli/graph.rs` (Mermaid), `migrate/` (legacy project -> `armadai-model`), `skills_registry/`, `starters_registry/`, `templates/`, and the integration tests and golden outputs in `tests/`.
- `crates/armadai-providers`: only a reader of the local models.dev catalogue cache (`model_registry/`; no network in this crate, nothing refreshes the cache) plus the tool-to-vendor table (`factory.rs`).
- `crates/armadai-secrets`: SOPS-based secret handling.
- `frozen/armadai-audit/`: the former `audit` command, frozen. It is outside the workspace and outside CI; do not build or edit it.

**State (steps 0-3 of v1 merged, step 3 in #472)**: every project command reads `.armadai/project.yaml` only; `armadai migrate` converts a legacy project (backup in `.armadai/.migrated/<ts>/`); `new`, native starter packs, flow templates and `graph` (Mermaid) are delivered. Codex, Copilot and OpenCode get their former output, fed from the model, with `not-compiled` report lines for what they do not cover yet (step 4, next). Specs: `docs/superpowers/specs/2026-10-12-step1-model-validator-migrate-design.md`, `docs/superpowers/specs/2026-10-12-step2-link-claude-design.md`, `docs/superpowers/specs/2026-10-13-step3-guided-creation-starters-design.md`.

**Non-obvious facts**:
- `crates/armadai` is **binary-only** — no `lib.rs`. `cargo test --lib` there returns "0 passed" with **no error**; use `--bin armadai` or `--test <name>`.
- There is no execution engine: flows are guidance (`CLAUDE.md`) plus, under `policy.delegation: strict`, links enforced by the gate. The legacy `OrchestrationPattern` is read only by the legacy parser (for `migrate`).
- There is no response-marker protocol any more (`ARMADAI_DELEGATE`/`END`/`META` were removed): delegation goes through each tool's native mechanism. The `PreToolUse` policy gate (`armadai __claude-policy-gate`) is installed by `link` in `settings.json` under `policy.delegation: strict` and reads `.armadai/project.yaml` at runtime (see `docs/wiki/policy-gate.md`).
- Test env isolation lives in `armadai_core::test_support` (behind the core's dev-only `test-support` cargo feature) and is **not reentrant** — two guards on one thread deadlock.

**Agent definition** lives in `.armadai/agents/<id>.md` (no user library any more). Templates in `crates/armadai/templates/*.md` are canonical agents (frontmatter with a default description); `new agent` sets description/tier/skills on the parsed frontmatter and renders `{{name}}`, `{{stack}}`, `{{description}}` in the body only. Flow templates (`pipeline`, `review-loop`, `plan-build-verify`, `fan-out`) and the Mermaid export are pure functions of `armadai-model` (`templates.rs`, `mermaid.rs`); `entry_steps` there is the one definition of an entry step (validator and gate).

**Config** lives in `~/.config/armadai/` (user: providers, secrets, templates, registries) and, per project, `.armadai/project.yaml`. `.armadai/` is versioned except `link-manifest.yaml` and `.migrated/` (`.armadai/.gitignore`).

## Git Conventions

- **Branch model** (master-only): `master` (default/trunk), `release/*` (release-line stabilization), `feature/*` branches. No `develop`.
- **Conventional Commits** enforced by `.githooks/commit-msg` hook and CI. Types: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `ci`, `perf`, `style`, `build`, `revert`
- **PR process**: Always squash merge to `master`, and merge only when Dimitri's brief authorises it (otherwise open the PR and stop, see `.claude/CLAUDE.md`). Before merging: check for Dependabot PRs, verify CI passes (all 6 checks: fmt, clippy, test, build, conventional commits, audit — one single configuration, no feature matrix).
- Enable hooks after clone: `git config core.hooksPath .githooks`
